ایندکس Biword در برابر ایندکس موقعیتی (Positional Index)

مبنای فصل: عکس جزوه؛ biword و موقعیت ↗ و متن تایپ‌شدهٔ جزوه. توضیح‌ها و مثال‌های تکمیلی به متن افزوده شده‌اند؛ این صفحه رونویسی کلمه‌به‌کلمه نیست.

ایندکس Biword

در ایندکس Biword، هر دو واژه متوالی متن به‌صورت یک اصطلاح مرکب ثبت می‌شوند. برای عبارت Data mining class دو biword داریم: Data mining و mining class.

  • مزیت: اجرای مستقیم برخی عبارت‌های دوواژه‌ای ساده است.
  • محدودیت‌ها: تعداد اصطلاحات و حجم ایندکس می‌تواند به‌شدت افزایش یابد (Index explosion). همچنین ترکیب نتایج biwordها در عبارت‌های بلند یا پرس‌وجوهای پیچیده ممکن است پاسخ‌های نادرست ایجاد کند؛ مثلاً ممکن است دو biword جداگانه در سند وجود داشته باشند، اما در یک موقعیت پیوسته قرار نگرفته باشند.

ایندکس موقعیتی (Positional Index)

در ایندکس موقعیتی، علاوه بر شناسه سند، موقعیت وقوع هر واژه نیز ذخیره می‌شود:

واژه → docID: <pos1, pos2, ...>

برای مثال، اگر واژه data در سند d7 در موقعیت‌های 3 و 10 ظاهر شود، بخشی از فهرست آن می‌تواند چنین باشد: d7: <3, 10>.

ادغام موقعیتی

برای یافتن عبارت دوواژه‌ای A B، ابتدا اسناد مشترک دو واژه پیدا می‌شوند، سپس موقعیت‌ها بررسی می‌شوند. اگر موقعیت‌ها از ابتدای صفرشماری یا یک‌شماری استفاده کنند، شرط مجاورت به شکل زیر است:

pos(B) = pos(A) + 1

برای جست‌وجوی مجاورتی با فاصله حداکثر k، شرط فاصله به‌صورت زیر نوشته می‌شود:

|pos(A) - pos(B)| ≤ k

در پیاده‌سازی دقیق‌ترِ عبارت با ترتیب مشخص، شرط موقعیتی باید جهت را نیز حفظ کند؛ یعنی موقعیت واژه بعدی پس از موقعیت واژه قبلی بیاید.

مثال‌ها

  • عبارت Stanford university Palo Alto نیازمند تطبیق واژه‌ها با ترتیب و فاصله درست است.
  • عبارت To be or not to be شامل واژه تکراری be است؛ فهرست موقعیت‌ها امکان تشخیص وقوع عبارت کامل و ترتیب دقیق آن را فراهم می‌کند.

مثال حل‌شدهٔ جست‌وجوی موقعیتی

data   → d1:[1,7], d2:[2]
mining → d1:[2,9], d2:[5]
class  → d1:[3],   d2:[6]

برای عبارت data mining فقط d1 پاسخ است، چون ۲ برابر ۱+۱ است؛ رخدادهای ۷ و ۹ مجاور نیستند. عبارت سه‌واژه‌ای data mining class نیز در d1 از موقعیت ۱ شروع می‌شود. اشتراک DocIDها فقط مرحلهٔ کاندیدسازی است، نه پاسخ نهایی.

مثبت کاذب Biword

سند data mining is useful; mining class starts today هر دو biword یعنی data mining و mining class را دارد، ولی عبارت کامل data mining class را ندارد. پس AND دو biword برای عبارت بلند کافی نیست و باید متن یا موقعیت‌ها بررسی شود.

قرارداد فاصله و واژه‌های تکراری

اگر فاصله را اختلاف موقعیت تعریف کنیم، |p2-p1| ≤ k یعنی اختلاف اندیس حداکثر k؛ اما اگر «تعداد کلمات بین دو واژه» منظور باشد، این تعداد |p2-p1|-1 است. ترتیب نیز باید مشخص باشد: برای نسخهٔ مرتب 0 < p2-p1 ≤ k.

برای to be or not to be تمام موقعیت‌های شروع باید با یک زنجیرهٔ مشترک بررسی شوند: to:p، be:p+1، or:p+2، not:p+3، to:p+4، be:p+5. حضور مستقل واژه‌ها کافی نیست.

1 / پرسش اصلی

آیا وجود همهٔ biwordها، وجود عبارت بلند را تضمین می‌کند؟

پاسخ را ببین

خیر؛ ممکن است در قسمت‌های جداگانهٔ سند باشند.

2 / گرم‌کردن

برای عبارت دوواژه‌ای A B، اگر A در موقعیت 7 باشد، B باید کجا باشد؟

پاسخ را ببین

در موقعیت 8 از همان سند؛ ترتیب و همسایگی هر دو مهم‌اند.

3 / یک محاسبهٔ کوتاه

در یک سند A=[2,8] و B=[3,10] است. آیا عبارت A B پیدا می‌شود؟

پاسخ را ببین

بله؛ موقعیت‌های 2 و 3 یک رخداد می‌سازند. 8 و 10 همسایه نیستند.

4 / حالا تو بگو

چرا A AND B الزاماً عبارت A B را پیدا نمی‌کند؟

پاسخ را ببین

AND فقط حضور هر دو واژه در سند را بررسی می‌کند؛ فاصله و ترتیب واژه‌ها را تضمین نمی‌کند.
